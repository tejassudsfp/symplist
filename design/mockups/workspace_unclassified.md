# Unclassified — unsorted capture

Read [overall.md](overall.md) and [themes.md](themes.md) first. Produce high-fidelity mockups for this surface and the states below. Closed-beta rules apply throughout.

## Screen and interaction brief

Design Unclassified for ideas and incoming tasks that have not been placed in Now or Later. Use the exact collection label; a shorter mobile label may be visually abbreviated only with an accessible full name. This is not email and should not inherit sender/time/subject conventions indiscriminately.

Sample tasks: “Look into a standing desk,” “Notes from the weekend,” and “Review the outline” with a subtle “Added by connected agent” source on one row. Source metadata is optional and must not clutter every item. Selecting a task still reveals its Markdown page and task-specific conversation.

Show quick capture, populated inbox, empty state, selected incoming task, and a compact row/menu action to move to Now or Later. The user can leave items unclassified; do not force a triage ceremony, progress score, or Inbox Zero celebration.

A proposed empty line: “Drop a thought here. Sort it when you're ready.” Include one optional miniature theme illustration. External automation setup is out of scope, so there should be no Create automation button or nonfunctional integration rule builder.

Demonstrate dragging to both destination icons and the equivalent mobile/keyboard Move to action. If source access is revoked, show task content the user still owns without a broken provider prompt on every row. Include a temporary loading and retry state consistent with the other inboxes.

## Handoff

Use the frame naming and theme coverage in overall.md. Annotate entry/exit, primary and secondary actions, focus behavior, responsive changes, and persistence expectations. Include meaningful error/loading states rather than only the successful screen. Reuse shared components; do not add unrequested billing or automation features.

## Keyboard coverage

Follow the shared [keyboard map](../../docs/notes/files/13_keyboard_shortcuts.md). Show applicable menu hints, visible focus, next/previous task behavior, Page/Chat focus switching, and search entry. Navigation shortcuts must not activate while the user types. Include keyboard-only operation in the prototype and preserve drafts when focus/tasks change.
